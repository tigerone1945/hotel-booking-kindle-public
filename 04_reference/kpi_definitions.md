# KPI定義(書籍第4章の計算ルール)

書籍の第4章で、著者が承認した計算ルールの要約です。**新しい定義や分析結果を加えていません。** 理由や考え方、演習は書籍にあります。KPIの定義は、ChatGPTではなく人が決めます。ChatGPTは、決まった定義どおりに計算する道具です。

数値は、書籍の基準版のCSV(119,390行)での値です。取得したCSVが基準版と違うときは、[取得ガイド](../01_getting_started/dataset_download_guide.md)を参照してください。基準値は[こちら](expected_values.md)です。

## KPI定義に書く6つのこと

分子／分母／集計の対象／使う列／Filter・除外条件／記録(いつ、誰が、どう決めたか)。

> 「原CSVを加工・削除する」ことは行いません。以下の「除外」は、**その集計だけ**、条件に合う行を数える意味です。

## ルール1:Booking Count(予約レコード数)

| 項目 | 内容 |
|---|---|
| 分子 | 対象の行数 |
| 分母 | 該当なし(件数の集計) |
| 集計の対象 | 予約レコード(CSVの1行) |
| Filter・除外条件 | 主分析では除外しない。全119,390行を数える |
| キャンセル・No-Show | 含む |

- CSVには予約番号の列がありません。「ユニークな予約数」「実際の予約件数」とは呼ばず、**「予約レコード数」**と呼びます。
- 完全に同じ内容の行(先頭を除いて31,994行)は、自動で削除しません。重複登録か別の予約かは、このCSVだけでは分からないためです。重複とみなして数え直すのは、別の比較(感度分析)です。

## ルール2:取消扱い率(No-Showを含む)

| 項目 | 内容 |
|---|---|
| 取消扱い | `is_canceled` が1の予約レコード(Canceled＋No-Show) |
| 分子 | `is_canceled` が1の予約レコード数 |
| 分母 | **同じグループの**、`is_canceled` が0か1と判定できる予約レコード数 |
| 率 | 分子 ÷ 分母 × 100(%) |
| 集計の対象 | 全体、ホテル別、Lead Time帯別など |
| 除外条件 | 判定できない行がある場合のみ、分母から外す(基準版にはない) |
| 表記 | 「取消扱い率(No-Showを含む)」 |

- 基準版の `reservation_status`:Check-Out 75,166／Canceled 43,017／No-Show 1,207(合計119,390)。取消扱いは 43,017＋1,207＝44,224。全体の取消扱い率は約37.04%。
- 分母は、分子と同じグループで決めます(例:リゾートホテルの率は、分子・分母ともリゾートホテルの行)。全体の119,390で割ったり、Check-Out件数で割ったりしません。
- CanceledとNo-Showは業務上の意味が違うため、内訳は別に表示します。「お客様が自分でキャンセルした割合」ではありません。率の高低の理由は、この定義だけでは分かりません。

## ルール3:`adr` 列の平均(主系列)

| 項目 | 内容 |
|---|---|
| 対象 | `reservation_status` が `Check-Out` で、`adr` が0以上の予約レコード |
| 計算式 | 対象レコードの `adr` 合計 ÷ 対象レコード数 |
| 0の値・高額の値 | 対象に残す(自動では除外しない) |
| 負の値 | この主系列の集計条件から外れる(原CSVからは消さない) |
| 補足 | 中央値なども併記する |

- 基準版:Check-Out 75,166件のうち、`adr` が負の1件が外れ、対象は75,165件。`adr` 列の平均は約99.99。
- 99.99には単位(通貨)がありません。ホテル業界の正式なADR(客室売上÷販売客室泊数)と同じ計算かどうかは、確認できていません。「ADR」ではなく**「`adr` 列の平均」**と呼びます。
- 全予約を含める、負の値を含める、0を除く、高額を除く、といった集計は、比較用(感度分析)です。
- **実際の売上や収益の指標ではありません。**

## ルール4:予約予定泊数と0泊

| 項目 | 内容 |
|---|---|
| 計算 | `stays_in_week_nights` ＋ `stays_in_weekend_nights` |
| 呼び方 | 「予約予定泊数」(実際に泊まった日数ではない) |
| 0泊の行(715件) | 0泊として保持する。平均や構成の計算にも含める |

## ルール5:人数と、人数0・欠損

| 項目 | 内容 |
|---|---|
| 計算 | `adults` ＋ `children` ＋ `babies` |
| 人数0の行(180件) | 0人として保持する。平均にも含める |
| `children` が `NA` の行(4件) | 人数の合計を確定できないため、**人数の指標だけ**から外す。0には置き換えない。ほかの集計(予約数、取消扱い率など)には含める |

180件は `children` が数値の行について数えた件数で、4件とは別です。

## ルール6:国の欠損とUndefined区分

| 対象 | 扱い |
|---|---|
| `country` が `NULL`(488件) | 表示上は **Unknown** として扱い、全体の母数に含める。原CSVの値は変えない。「国が存在しない」という意味ではない |
| `market_segment` の `Undefined`(2件)、`distribution_channel` の `Undefined`(5件) | 独立した区分として、構成比の分母に含める |

## ルール7:Lead Timeなどの区分

| 区分 | 境界 |
|---|---|
| Lead Time帯 | 0日／1〜7日／8〜30日／31〜90日／91〜180日／181〜365日／366日以上 |
| 長期滞在 | 予約予定泊数が7泊以上 |

この境界は、探索のための暫定的な区分です。「この境界で施策を打つべき」という意味ではありません。境界を変えると、見え方が変わることがあります。

## ルール8:参考推定予約金額

| 項目 | 内容 |
|---|---|
| 計算 | `adr` × 予約予定泊数 |
| 対象 | `adr` が0以上で、予約予定泊数が数値の行 |
| 位置づけ | 補助的な参考値。主たる指標としては使わない |
| 系列 | Check-Outの予約と、取消扱いの予約を分けて集計する |

実売上、会計上の売上、確定損失、利益では**ありません**。通貨、キャンセル料の有無、空いた客室を他の予約で売れたかどうかが、分かっていないためです。取消扱いの予約の金額を「逃した売上」「失った売上」とは書けません。

## 注意

- ルール1〜8は、書籍の説明のための呼び名です。
- この定義は、書籍の分析のための取り決めです。業務で使うときは、ご自身の業務に合わせて人が決め、記録してください。
